# MailClient

Visual Studio 2022 (17.12+) / C# / .NET 9.0 / Windows Forms 메일 클라이언트. 메일 통신은 [MailKit](https://github.com/jstedfast/MailKit)을 사용합니다.

## 빌드 / 실행
- `MailClient.sln` 을 Visual Studio 2022에서 열고 F5
- 또는 `dotnet run --project MailClient`

## 릴리스 (msix / zip)
`.github/workflows/release.yml` 이 GitHub Actions 에서 빌드합니다. 패키징은 `build/Package.ps1` 이 하므로 로컬에서도 같은 결과를 만들 수 있습니다.
- `v1.2.3` 형식의 태그를 push 하면 GitHub Release 를 만들고 다음 파일을 올립니다.
  ```
  git tag v1.2.3
  git push origin v1.2.3
  ```
  - `MailClient-1.2.3-x64.msix`: 서명된 설치 패키지
  - `MailClient-1.2.3-win-x64.zip`: 압축을 풀고 `MailClient.exe` 실행 (.NET 런타임 포함, 설치 불필요)
  - `MailClient.cer`: msix 서명 인증서 (공개 키)
- Actions 탭에서 수동 실행하면 Release 없이 Actions 아티팩트로만 올립니다.
- 로컬: `pwsh build/Package.ps1 -Version 1.2.3 [-CertificatePath x.pfx -CertificatePassword ...]` → `dist/`

서명 인증서는 저장소 시크릿 `MSIX_CERTIFICATE`(.pfx 를 base64 로 인코딩한 값)와 `MSIX_CERTIFICATE_PASSWORD` 로 지정합니다.
없으면 빌드할 때마다 임시 자체 서명 인증서(`CN=MailClient`)로 서명하므로, 릴리스마다 인증서를 다시 신뢰해야 합니다.

자체 서명 msix 설치: `MailClient.cer` 를 **로컬 컴퓨터 > 신뢰할 수 있는 사람** 저장소에 가져온 뒤(관리자 권한) msix 를 엽니다.

msix 로 설치하면 `%AppData%\MailClient\` 에 새로 만드는 파일이 패키지 전용 위치로 리디렉션되어, 앱을 제거하면 함께 지워집니다.
zip 버전과 데이터를 공유하려면 메일 저장소 위치나 `MAILCLIENT_DATA` 를 지정하세요.

## 기능
| 기능 | 위치 |
|---|---|
| 계정 등록 (IMAP / POP3 + SMTP, Gmail·Outlook·Naver·Daum 프리셋, 연결 테스트) | 파일 > 계정 편집 (메일 계정 목록의 추가 / 편집 / 삭제) |
| 계정별 트리: Inbox / Sent Items / Junk Email / Deleted Items (계정을 접으면 Inbox 에 읽지 않은 메일이 있을 때 계정 이름이 굵게) | 왼쪽 패널 |
| **Archive**: 계정과 별개인 로컬 보관함. 메일을 끌어다 놓아 보관, 오른쪽 클릭으로 하위 폴더 추가·이름 바꾸기·삭제 (여러 단계 가능) | 왼쪽 패널 맨 아래 |
| Inbox 목록을 받은 날짜로 구획 (Today / Yesterday / This Week / One·Two·Three Weeks Ago / Last Month / Older, 접기 가능) | 오른쪽 목록 |
| 메일 이동: 목록에서 트리 폴더로 드래그, 또는 메시지 > 다른 폴더로 이동 / 우클릭 메뉴 | 오른쪽 목록 |
| 주기적 새 메일 확인 (기본 5분, 1~1440분) | 도구 > 설정 > 일반 |
| Windows 시작 시 자동 실행 (HKCU\Software\Microsoft\Windows\CurrentVersion\Run 에 등록, 체크 상태는 레지스트리에서 읽음. msix 설치 버전은 미지원) | 도구 > 설정 > 일반 |
| 화면 잠금을 풀면 약 5초 뒤 자동으로 보내기/받기 | 자동 |
| 메일 쓰기 / 읽기 / 회신 / 전체 회신 / 전달 (첨부 포함). 메일 보기 창에서 Ctrl+D 는 삭제 후 창 닫기 | 툴바, 메시지 메뉴 |
| 받는 사람 추천: 받은 편지함에서 읽은 메일의 보낸 사람을 기억해 두고(no-reply 주소 제외), 받는 사람·참조·숨은 참조에 입력한 글자가 주소나 이름에 들어 있으면 목록으로 추천 (↑/↓, Enter/Tab, Esc, 마우스). 저장된 목록은 도구 > 설정 > 보낸 사람 에서 검색·삭제, [지금 추가]로 받은 편지함의 이미 읽은 메일에서 한 번에 추가 | 메일 쓰기 창, 도구 > 설정 > 보낸 사람 |
| 정크 메일 판정 + 예외(허용) 주소·도메인, 차단 주소·도메인, 키워드 | 도구 > 설정 > 정크 메일 |
| 규칙: 지정한 보낸 사람에게서 온 새 메일을 지정한 폴더에 .eml 로도 저장 (여러 규칙을 목록으로 추가/편집/삭제, 파일 이름은 "받은 날짜 시각 제목.eml"). 메일 우클릭 > 규칙 작성으로 그 메일의 보낸 사람을 채워 바로 추가 | 도구 > 설정 > 규칙, 메일 우클릭 메뉴 |
| 최신 버전 업데이트: GitHub Release 의 최신 버전을 받아 설치 (msix 는 앱 설치 관리자, zip 은 실행 폴더의 파일을 바꾸고 다시 실행) | 도움말 > 최신 버전 업데이트 |

삭제(Del)하면 Deleted Items로 이동하고, Deleted Items에서 다시 삭제하면 영구 삭제됩니다.

### IMAP 서버에 변경 반영 (계정 옵션)
계정 창의 **"이동·삭제·읽음 표시를 서버에도 반영 (IMAP)"**을 켜면(새 계정은 기본으로 켬, 기존 계정은 꺼짐) 이 프로그램에서 한 동작이 서버에도 적용됩니다.

| 이 프로그램 | IMAP 서버 |
|---|---|
| 읽음 / 읽지 않음 표시 | `\Seen` 플래그 설정 / 해제 |
| Junk Email 로 이동 / 정크 아님 | 서버 정크(스팸) 폴더 ↔ INBOX |
| 삭제 (Deleted Items 로 이동) / 복원 | 서버 휴지통 ↔ 원래 폴더 |
| 영구 삭제 | 서버 휴지통으로 옮긴 뒤 휴지통에서 삭제 |

- 서버 폴더는 SPECIAL-USE 표시(`\Trash`, `\Junk`, `\Sent`)로 찾고, 없으면 흔한 이름(Trash, Spam, Deleted Items, 휴지통 등)으로 찾습니다.
- 변경은 `mail.db`의 대기열에 쌓였다가 약 1.5초 뒤, 그리고 메일 확인 때마다 순서대로 보냅니다. 오프라인이어도 잃지 않고 나중에 보냅니다. 같은 변경이 5번 실패하면 포기하고 로그에 남깁니다.
- 받은 메일을 정크 필터가 자동으로 Junk Email 에 넣는 것은 서버에 반영하지 않습니다(서버에서는 INBOX 그대로).
- 서버 → 이 프로그램 방향의 읽음 표시는 반영하지 않습니다. 삭제는 아래처럼 받은 편지함에 한해 반영합니다.

### 서버에서 삭제된 메일 정리 (모든 IMAP 계정)
보내기/받기 때마다 **최근 1주일(메일 날짜 기준) Inbox 메일과 최근 20개 Inbox 메일**(둘 중 하나에 해당하면 확인)이 서버 INBOX 에 아직 있는지 확인하고, 없으면(다른 기기에서 삭제·이동) 로컬에서도 **Deleted Items** 로 옮깁니다. 복원하면 다시 Inbox 로 돌아옵니다.
- UID 와 Message-ID 로 모두 찾지 못한 메일만 옮기고, 서버 확인 중 오류가 나면 아무것도 옮기지 않습니다.
- 서버에 아직 보내지 못한 변경이 있는 메일, Junk Email 등 다른 폴더의 메일, 1주일보다 오래되고 최근 20개에도 들지 않는 메일은 건드리지 않습니다.

## 인증 관련 참고
- **Gmail**: 2단계 인증을 켠 뒤 발급한 *앱 비밀번호*를 쓰거나 OAuth(Google)를 사용합니다.
- **Outlook.com / Microsoft 365**: Microsoft가 비밀번호(기본) 인증을 막았기 때문에 **OAuth가 필요**합니다.
  앱에 기본 클라이언트 ID가 들어 있으므로 계정 창에서 **OAuth 로그인**만 누르면 됩니다.
- **Google OAuth**: 앱에 기본 클라이언트가 없으므로, 계정 창의 "직접 등록한 클라이언트 ID 사용"에
  Google Cloud Console의 *데스크톱 앱* OAuth 클라이언트(범위 `https://mail.google.com/`) ID와 비밀을 입력합니다.

### OAuth 클라이언트 ID (앱 기본값)
- 기본값은 `MailClient/oauth-clients.json` 에 있고 **실행 파일에 포함**되어 배포됩니다.
  다시 빌드하지 않고 바꾸려면 같은 형식의 `oauth-clients.json` 을 `MailClient.exe` 옆에 두세요(비어 있지 않은 값만 덮어씀).
- 클라이언트 ID는 비밀이 아닙니다(로그인 때 브라우저 주소에 그대로 보임). 데스크톱 앱은 PKCE로 보호하며,
  보호 대상은 사용자별 Refresh Token(DPAPI 암호화)입니다.
- 계정 창의 "직접 등록한 클라이언트 ID 사용 (고급)"은 회사 정책 등으로 자체 앱 등록이 필요할 때만 씁니다.
  이 값만 계정에 저장되고 내보내기에 포함되며, 기본값은 내보낸 파일에 들어가지 않습니다.
- Refresh Token은 발급받은 클라이언트에 묶여 있어 그 클라이언트로 갱신합니다. 기본값이 바뀌어도 기존 로그인은 유지됩니다.
- Microsoft 앱 등록 조건: 지원 계정 "모든 조직 디렉터리의 계정 및 개인 Microsoft 계정", 플랫폼 *모바일 및 데스크톱*,
  리디렉션 URI `http://localhost`, 클라이언트 암호 없음.

비밀번호와 토큰은 Windows DPAPI(현재 사용자 범위)로 암호화해 저장합니다.

## 데이터 저장 위치
`%AppData%\MailClient\` (환경 변수 `MAILCLIENT_DATA` 로 바꿀 수 있습니다)
- `settings.json`: 계정과 설정 (비밀번호와 토큰은 DPAPI로 암호화)
- `mail.db`: 메일 저장소 (SQLite)
  - `messages`: 메일 정보(폴더, 읽음, 제목, 보낸 사람 등), 원본 메일(`raw`, MIME BLOB), 검색용 본문 텍스트(`body_text`)
  - `sync_state`: 계정별 서버 동기화 상태 (IMAP UID / POP3 UIDL)
  - `server_ops`: IMAP 서버에 아직 반영하지 못한 변경 대기열

### 메일 저장소 위치 바꾸기
**도구 > 설정 > 일반 > 메일 저장소**에서 `mail.db` 대신 쓸 파일을 지정할 수 있습니다([기본 위치]로 되돌림).
- [확인]을 누르면 진행 중인 메일 확인을 멈추고 그 파일을 열어 트리와 목록을 다시 그립니다.
- 파일이 없으면 **현재 메일을 복사**(일관된 스냅숏)하거나 **빈 저장소로 시작**할지 묻습니다. 빈 저장소는 메일 확인 때 서버에서 최근 메일을 다시 받습니다.
- SQLite 가 아닌 파일이나 다른 프로그램의 데이터베이스는 열지 않고 기존 저장소를 계속 씁니다.
- 시작할 때 지정한 파일을 열 수 없으면(드라이브 분리 등) 그 실행 동안 기본 위치를 쓰고 안내합니다. 설정 값은 남아 다음 실행에 다시 시도합니다.
- 이 경로는 PC마다 다르므로 설정 내보내기에는 포함되지 않습니다.

이전 버전의 `Data\{계정ID}\*.eml` 파일 저장소는 처음 실행할 때 `mail.db`로 자동으로 옮겨지고,
원래 폴더는 `Data.migrated-날짜` 로 이름을 바꿔 남겨 둡니다. 메일이 정상적으로 보이면 지워도 됩니다.

계정 목록은 **[파일] → [계정 편집]** 창에서 JSON으로 **내보내기/가져오기**할 수 있습니다.
옮길 계정을 골라 선택할 수 있고, "도구 > 설정" 내용(메일 확인 주기, 알림, 정크 메일 필터와 목록)도 체크박스로 함께 포함할 수 있습니다.
설정에는 비밀 값이 없어 평문으로 저장되며, 설정만 내보낼 때는 본인 확인과 암호가 필요 없습니다.
비밀번호와 토큰은 입력한 암호로 암호화되며(PBKDF2-SHA256 + AES-256-GCM), 가져올 때 같은 암호가 필요합니다.

내보내기 전에는 **현재 로그인한 Windows 사용자 본인 확인**을 거칩니다.
- Windows Hello(PIN/지문/얼굴)가 설정되어 있으면 "Windows 보안" 확인 창을 사용합니다.
- 그렇지 않으면 "Windows 보안" 암호 창에 Windows 로그인 암호를 입력합니다. 다른 계정의 암호로는 통과할 수 없습니다.
- 확인 결과(성공/취소/실패와 방식)는 `mailclient.log`에 기록됩니다. 암호는 기록하지 않습니다.

Windows Hello API를 쓰기 때문에 **Windows 10 버전 2004(빌드 19041) 이상**이 필요합니다.

폴더 구성과 이동은 **로컬에서 관리**합니다. 서버에서는 받은편지함(INBOX)의 새 메일만 가져옵니다.
POP3에서 "서버에 사본 남기기"를 끄면 받은 뒤 서버에서 삭제됩니다.
